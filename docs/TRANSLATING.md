# Translating AutoScene

AutoScene's words live in catalogs under `app/src/locales/`. English is the source. Another language is a folder
next to it, `app/src/locales/<language>/`, with the same files. This page says how a translation is made and kept
current, then gives the Romanian glossary and style, which a translator follows as written.

**Romanian is offered and is still a draft.** It is on `OFFERED` in `app/src/lib/i18n.ts` and in `SPOKEN`
(`app/src-tauri/src/locale.rs`), so Settings → General → App language chooses it and Automatic takes it from the
system. Every message stays `draft` in `ro/meta.json` until moongetsu has checked it.

## What is where

| File | Holds |
|---|---|
| `locales/en/<namespace>.ts` | English, the source. A comment above a key is a note for the translator: button or title, what a `{{variable}}` holds, where it shows |
| `locales/en/backend.json` | what Rust says (errors, job titles and stages, plugin refusals). Generated by `cargo xtask i18n`, never edited by hand |
| `locales/en/native.json` | what Rust draws itself: the macOS menu, the system's dialogs, words written into exports. Edited by hand; Rust reads it through `native_text.rs` |
| `locales/ro/<namespace>.json` | Romanian, the same nesting and the same keys, with Romanian plural forms |
| `locales/ro/meta.json` | for every Romanian message: its state and the English it was made from |
| `locales/locales.test.ts`, `locales/check.ts` | the tests that hold all of the above together |

The namespaces are `common`, `shell`, `ui`, `shortcuts`, `settings`, `cast`, `project`, `library`, `media`,
`player`, `pack`, `export`, `plugins`, `backend` and `native`. A key is `namespace:area.item`, in lowerCamelCase,
and names the role of the text, not its wording. `_one`, `_few` and `_other` are plural suffixes.

## How a message is made and kept

Each message of `ro/meta.json` is `"cast:selection.hide": { "state": "draft", "en": "1a2b3c4d" }`. Its key is the
message's key without the plural suffix: a message with `_one`, `_few` and `_other` forms is one entry.

- **`state`** is who stands behind the Romanian:
  - `draft`: we translated it, nobody who speaks Romanian has checked it.
  - `reviewed`: a Romanian speaker (the owner's friend moongetsu) checked it.
  - `stale`: the English changed and the Romanian was not brought along. A stale message has **no text** in
    `ro/*.json`, so the app shows the English for it, never a translation of words that have changed. Its old
    Romanian is kept in the entry, as `"was"`, for whoever translates it again.
- **`en`** is eight hex letters, a hash of the English the Romanian answers: the message's texts, plural forms in
  the order `one`, `other`, then a plain text beside them, joined by line breaks, run through FNV-1a
  (`messageHash` in `locales/check.ts`). Any edit to any of the English texts changes it.

`locales.test.ts` refuses a catalog that breaks the rules below. Each failure names the key and what is wrong.

- A language has every message of the English and no other (a stale one excepted), in every namespace, `backend`
  and `native` included.
- A message with plural forms has the forms of the language, from `Intl.PluralRules`: English `one` and `other`,
  Romanian `one`, `few` and `other`. A plain text may sit beside them under the same key (`hide` and `hide_one`);
  it is what `t()` reads without a count, and it needs its own translation.
- The same `{{variables}}` with the same formats (`{{n, number}}` is not `{{n}}`: the first groups its digits),
  the same `$t(key)` references and the same tags as the English, in any order. A plural form is held against the
  English form of its name, or `other` when the English has none (`few`).
- Tags only from `b strong em mono key x go` (and the self-closed `what repo commit path`), never an HTML void
  name (`link br img input hr meta area base col embed source track wbr`); no empty text; a plugin's toast starts
  with fixed words and has `{{name}}` before any other variable.
- Romanian has no cedilla (ş ţ Ş Ţ, U+015E U+015F U+0162 U+0163), only the comma below (ș ț Ș Ț).
- Every message has a meta entry, with a state that is one of the three, and no meta entry names a message the
  English lacks.
- The `en` of a draft or reviewed entry is the hash of the English as it is now.

### When the English changes

The test fails for every message whose English changed, and says the hash it has now. Then, for each:

1. **Update the Romanian** to say what the English says now, and change its `en` to the hash the test printed.
   A `draft` stays a `draft`. A `reviewed` message that changed goes back to `draft`: the reviewer saw other words.
2. Or, when you can't translate it now, **mark it stale**: delete its text from `ro/<namespace>.json` (every
   plural form), set `"state": "stale"`, `"en"` to the new hash and `"was"` to the old Romanian (a plural
   message's forms written as one text, one form after another).

A new English message is a failing test too ("missing"): translate it, then add its entry (`draft`, with the
hash). A removed one fails as "not in the English" and "meta entry for a key the English hasn't": delete both.

There is no command for this yet. The design's `npm run i18n -- sheet`, `stale` and `reviewed` (a review sheet
for the reviewer, the stale move above, and flipping states) have not been written: until they are, the files
are edited by hand and the test is the check. To fill in a hash without counting by hand, run the test and copy
the one it prints.

### Review

The reviewer reads every `draft`, notably the entries the glossary marks **[check]**, and sends fixes. A fix is
a commit that changes the Romanian and flips the entries it checked to `reviewed`. We never comment on GitHub for
the reviewer: the owner relays.

### Looking at a language

`?lang=pseudo` on the mock (`npm run dev:mock`, then add it to the address) shows every catalog string accented
and 35 % longer, in brackets: anything shown plain is still written into the code, and anything cut off will be
cut off in Romanian too. `?lang=ro` shows the Romanian catalog while developing, whatever Settings says; a language
on `OFFERED` is chosen in Settings → General → App language.

### Where AutoScene's language ends

- **Automatic** takes the first language on the system's list that AutoScene speaks, English when it speaks none.
- **macOS** takes a per-app language in System Settings → Language & Region → Applications, because
  `Info.plist` names the languages (`CFBundleLocalizations`), and Automatic follows it. AppKit's own four items
  (Services, Start Dictation, Emoji & Symbols, Enter Full Screen) follow the macOS language. A language chosen in
  AutoScene that differs from macOS's therefore leaves those four in the macOS language; AutoScene doesn't write
  `AppleLanguages`.
- **What a plugin says** is never translated: its name, summary, strings and the text it shows. Plugin pages can
  read the language (`app.locale`) and match it themselves (`docs/PLUGINS.md`).
- **Numbers, sizes, dates and lists** are written by `fmt` (`@/lib/i18n`), never in a catalog; a catalog holds the
  templates around them.
- **What Discord shows** is English, always: the status lines are written in Rust (`discord.rs`) for the people who
  read them on Discord, not for the person, and the preview in Settings → Discord shows those same lines. The row
  that holds the preview says so. An owner decision, open: say them in the person's language through `native.json`.
- **Where a model comes from** (the manifest's `source` and `license` on Settings → About) stays English: names of
  papers, projects and licences. What each model is for, and what each contributor did, are in the catalog
  (`about.models.purpose`, `contributors.role`) and a test holds them to `models/manifest.toml` and
  `contributors.json`; a model or a person added there without a key shows the English until it has one.
- **Exports for scripts** keep their English format and headers (cut lists, EDLs), and the default library folder
  keeps its English name.

### Adding a language

1. Make `locales/<code>/` with a `.json` for every namespace of the table above (`backend` and `native` too),
   keys and nesting as in English, plural forms the language's own.
2. Add its entries to `<code>/meta.json`, every one a `draft` with the hash of its English.
3. Write its glossary and style on this page, as the Romanian has, before the first message is translated.
4. Add the language to `LANGUAGES` in `lib/i18n.ts` and to the loaders in `locales/index.ts`, and run
   `locales.test.ts`.
5. Offer it: `OFFERED` and `LANGUAGE_NAMES` (`lib/i18n.ts`, its own name) and `SPOKEN` together, `UiLanguage` and
   `Lang` (`as-api`), `native.json` in `CATALOGS` (`native_text.rs`) and the language in `Info.plist`.

## Romanian

Everything here is a draft until moongetsu has checked it (`ro/meta.json` state `draft`). Lines marked **[check]** are
choices a Romanian editor may want otherwise; they are listed again at the end, most important first. A translator
follows this page as written and never decides a term alone: a word that is missing here is reported, not invented.

The rule behind all of it: **one thing, one Romanian word**, in every namespace, in `native.json` and in `backend.json`.
The voice is the English voice of `docs/DESIGN.md` (Copy): plain, confident, an editor's words, no marketing, no
exclamation marks. It should read as if written in Romanian, not as English with Romanian words: move the sentence
around, drop a possessive, split a sentence. Keep the sense, not the shape.

### Register: tu

- Speak to the person as **tu**, everywhere, including errors, dialogs, plugin warnings and the macOS menu. Never
  `dumneavoastră`, `dvs.`, plural imperatives (`Salvați`), or impersonal infinitives. Never "vă rugăm", "te rog",
  "ne pare rău". The English has no please and no sorry.
- `tău`, `ta`, `tăi`, `tale` stay lower case. Use them only when it matters whose it is: "Numele și deciziile tale rămân."
- Whole forms, calm rather than spoken: `este`, `nu este`, `nu a`, `nu s-a`. Not `e`, `n-a`, `n-o`.
  Clitics Romanian requires stay (`s-a`, `l-a`, `s-au`, `într-un`, `într-o`).
- The app speaks of itself by name in the third person: "AutoScene a retras pluginul", never "am retras".
- Plain Romanian before loan verbs: `schimbă`, not `customizează`; `dă clic`, not `fă click`; `setează` only for a
  plugin's secret or value (Set…). `a rula` is fine for programs.

### Which form for which text

| Text | Form | Example |
|---|---|---|
| Button, menu entry, ⋯ entry, tooltip of a control, switch label | **imperative, 2nd person singular.** Never an infinitive (`a salva`), never a long infinitive noun (`Salvare`) | Salvează · Exportă clipul · Arată în folder · Caută actualizări automat |
| Negative button | `Nu` + the infinitive without `a` | Nu mai arăta |
| Page, section, dialog and menu titles, field labels, tabs | noun | Setări · Distribuție · Format · Fișier · Editare |
| A dialog that asks | question in the **present indicative**, then the answer button in the imperative | Instalezi {{name}}? → Instalează · Elimini „{{name}}”? → Elimină |
| Work in progress ("Indexing", "Finding shots") | reflexive present. Never a gerund (`indexând`) | Se indexează · Se caută planurile · Se exportă {{total}} clipuri |
| The same, as a word in a list (`stopsFirst`) | noun with article | indexarea · un export |
| Done ("Saved the EDL", "Copied timecode", "Hid 3 characters") | participle after its noun; with a value: participle, colon, value | EDL salvat · Timecode copiat · Dezinstalat: {{name}} |
| Failed (status) | `a eșuat`, no agreement to get wrong | Analiza a eșuat · A eșuat |
| "Couldn't X" (about 115 keys) | `Nu s-a putut` + infinitive without `a`; **`Nu s-au putut` when the thing is plural** | Nu s-a putut salva setarea · Nu s-au putut copia timecode-urile · Nu s-a putut deschide {{label}} |
| "No X yet" | `Încă nu există` | Încă nu există personaje |
| "Nothing matches" | one form | Nu s-a găsit nimic. |
| Sentences with subject and verb | a finished sentence, with a full stop where the English has one | Detaliile sunt în jurnal. |

- A key whose note says it serves as both button and title is a bug in the catalog: report it, as Romanian needs two
  keys (`docs/DESIGN.md`: one key per meaning).
- **A third-person line that looks like a button.** `Citește`, `Folosește`, `Exportă` are both "reads" and "read!".
  So a plugin's permission and capability lines start with **`Poate`**: "Poate citi clipurile exportate", "Poate
  comunica cu aceste site-uri, doar prin https:", "Poate folosi placa video". Permission lines must never read as
  a command, in `plugins` and in `native.json` alike.
- Sentence case everywhere, the macOS menu too: only the first word and proper names get a capital. Named places keep
  their capital inside a sentence: "în Setări → General", "Este în Activitate." Fast Scan is not a name in Romanian:
  "Scanare rapidă" as a label, "scanarea rapidă" in a sentence.

### What is never translated

- Names of products, formats and services (the list of `locales/hardcoded.test.ts`): AutoScene, AniList, TVmaze, Fandom,
  Wikidata, InsightFace, Scener, ProRes, DNxHR, H.264, HEVC, AV1, WebM, MKV, MOV, Dolby and all that follows it,
  symbols, `S01E03`.
- And, from the catalogs: NVIDIA, GeForce RTX, FFmpeg, ONNX Runtime, DirectML, Core ML, GitHub, Discord, Twixtor,
  Premiere, Resolve, Finder, Mac, macOS, Windows, Linux, Python, uv, WebAssembly, MP4, TS, EDL, CSV, HDR, GOP, CC BY-SA,
  Bit-Perfect, All-Intra, Mono, Stereo.
- Editors' English that Romanian editors use as it is: scenepack, timecode, timeline, fade in, fade out, anime, plugin,
  fps.
- The keyboard: key caps as printed (`Ctrl`, `Shift`, `Esc`, `Enter`, `Backspace`, `Del`, `Ins`, `Page Up`, `Page Down`,
  `Space`).
- Code: `plugin.json`, `.asp`, `manifestVersion`, `contributes.*`, `wasm32-wasip2`, `componentize-py`, `https`, a name
  part's token. `{{variables}}`, `{{found, number}}` and tags (`<x>`, `<mono>`, `<b>`, `<what/>`…) are copied byte for
  byte; they may move, and the catalog test checks they are all there.
- What is in the export for scripts: the format and headers of cut lists and EDLs. The default library folder's name.
- The person's data and the plugin's words, which are values.

Words that end as they are spelled take endings directly; a silent letter at the end takes a hyphen (DOOM3).

| Word | Article | Plural | Plural with article |
|---|---|---|---|
| scenepack | scenepackul | scenepackuri | scenepackurile |
| plugin | pluginul | pluginuri | pluginurile |
| clip | clipul | clipuri | clipurile |
| timecode | timecode-ul | timecode-uri | timecode-urile |
| timeline | timeline-ul | timeline-uri | timeline-urile |
| site | site-ul | site-uri | site-urile |

All of them are neuter, as are `plan`, `cadru`, `personaj`, `episod`, `fișier`, `export`, `proiect`: masculine in the
singular, feminine in the plural. "1 plan omis", "3 planuri omise". `față` is feminine, so "All are {{name}}" =
"Toate sunt {{name}}".

### Plurals

Keys are `_one`, `_few`, `_other`. English has `_one` and `_other`, so **Romanian adds a `_few` to every plural key**,
and the catalog test refuses a key without it. The form is chosen by `count` (`Intl.PluralRules("ro")`), and the number
written may be another variable (`{{total}}`).

| Key | Counts | Form |
|---|---|---|
| `_one` | 1 | 1 față · 1 plan |
| `_few` | 0, 2 to 19, 101 to 119, 1.001 to 1.019…, any decimal | 0 fețe · 3 planuri · 119 fețe |
| `_other` | 20 to 100, 120 to 200…, 1.000, 14.200 | **20 de fețe** · 120 de planuri · 14.200 de fețe |

```json
"faces_one": "{{count}} față",
"faces_few": "{{count}} fețe",
"faces_other": "{{count}} de fețe",
"failed_one": "Nu s-a putut verifica {{count}} plan",
"failed_few": "Nu s-au putut verifica {{count}} planuri",
"failed_other": "Nu s-au putut verifica {{count}} de planuri",
```

- `de` goes between the number and its noun, and only in `_other`. No noun after the number means no `de`: "și încă
  {{count}}", "încă {{count}} în acest episod". The supine `de verificat` stays in all three: "{{count}} de verificat".
- Verb and participle agree too: `_one` singular, `_few` and `_other` plural.
- Where the English `_one` reads as a plural ("{{count}} shots", as both forms read the same there), write the true
  singular: "{{count}} plan".
- With "X of Y" the plural follows Y: "{{done}} din {{count}} episod", "… episoade", "… de episoade".
- A `{{n}}` with a noun beside it and **no plural keys** can't be right from 20 on ("24 cadre"). Write the noun first or
  use the short unit: "Episoade: {{n}}", "Margini {{n}} c", "{{n}} ep.". Never add a plural key alone: it needs the
  English key too, so report it.

### Names and other values

A value can't be inflected, and a character's gender is unknown.

- **No genitive around a value:** no `lui {{name}}`, nothing shaped like `{{name}}'s`. Use a preposition that leaves
  the name as it is, or a colon: "Scenepack pentru {{name}}", "{{count}} planuri cu {{name}}", "Tastele din {{preset}}",
  "Opțiuni: {{name}}", "Alege o imagine pentru {{name}}".
- **No `el`, `ea`, `lui`, `ei`, `său`, `sa` for a character.** English "they/their" hides the gender; Romanian can't.
  Drop the pronoun, or say `personajul`: "Fața nu se vede", "Arată planurile", "Doar personajul în plan", "Nu este
  personajul" (Not them). "Is this {{name}}?" = "Este <x>{{name}}</x>?"; "Who is this?" = "Cine este?"; "No, someone
  else" = "Nu, altcineva". `Singur` and other adjectives that must agree with a person are avoided: "Not alone" =
  "Cu alte personaje".
- **Drop possessives** the English needs and Romanian doesn't: "Its settings" = "Setări", "Show its log" = "Arată
  jurnalul", "Its folder" = "Folderul".
- **No agreement with a value.** "Uninstalled {{name}}" = "Dezinstalat: {{name}}", "Removed “{{title}}”" = "Eliminat:
  „{{title}}”". A fixed noun carries the agreement if the sentence needs one: "Pluginul {{name}} a fost oprit."
- `{{why}}`, `{{reason}}` and similar fragments start lower case and have no full stop, as the English. Write them to
  stand after a colon.

### Letters

- **Comma below only:** ș U+0219, ț U+021B, Ș U+0218, Ț U+021A. Never the cedilla forms U+015F, U+0163, U+015E, U+0162.
  The catalog test refuses the two lower-case ones; a text pasted from an old source is the usual cause.
- ă, â, î as DOOM3: `â` inside a word (`când`, `România`), `î` at its start and end and after a prefix (`încarcă`,
  `reîncarcă`, `neîncărcat`); `sunt`, never `sînt`.

### Numbers and dates

They come from `fmt`, and the catalog never writes them by hand. `count` is grouped, while `{{year}}`, `{{width}}` and
`{{total}}` stay raw.

| | English | Romanian |
|---|---|---|
| number | 14,200.5 | 14.200,5 (the dot from four digits on: 1.234) |
| size | 1.5 GB | 1,5 GB |
| percent | 50% | 50 % |
| date and time | 13 Oct, 20:13 | 13 oct., 20:13 (24-hour clock) |
| a day | 3 November 2026 | 3 noiembrie 2026 |
| list | A, B and C | A, B și C (no comma before `și`) |

- Months, days and language names are lower case in a sentence. A language in a list gets its capital from `fmt`.
- A day in a sentence takes `pe`: "Verificat pe {{date}}.", "lansat pe {{date}}"; `azi`, `ieri`.
- Timecodes, frame numbers in examples, `S01E03`, `1x03` and `+48` stay exactly as typed: "00:12:03:05", "17099".
- Units stay international with no full stop: `s`, `min`, `h`, `B`, `KB`, `MB`, `GB`, `TB`, `fps`. In `common:format.*`
  and the player's `percent` a number and its unit are joined by a no-break space, written ` ` in the JSON, as
  `Intl` does: `"{{value}} %"`.
- Word abbreviations end in a full stop: `ep.`, `can.` ("{{n}} can.").
- The unit for frames is **`c`** **[check]**: `frameUnit`, "Margini {{n}} c". The bit depth is `{{n}} biți`.
- `about` = `circa`, which takes no `de`: "Circa {{size}} în total ca {{format}}."
- Time left, lower case, as it follows a stage: `aproape gata`, `încă {{s}} s`, `încă circa {{m}} min`,
  `încă circa {{h}} h`. On screen: "Se caută planurile · încă circa 3 min".
- A range in words: "între {{min}} și {{max}} s". Between two timecodes the catalog's ` – ` stays.

### Punctuation

- **Quotes:** „…” (U+201E, U+201D) for every “…” of the English: „{{name}}”, also `shortcuts:quote`. Quotes inside quotes:
  «…». Punctuation that belongs to the sentence goes after the closing quote. Never a straight " in a text.
- No apostrophe: Romanian joins with a hyphen, and `'s` has no equivalent (see Names and other values).
- `…` is one character, U+2026, with no space before it. It stays on the entries that have it: "Setări…", "Mută în…".
- For the English dash in a sentence, a colon or a semicolon reads better; if a dash stays, a spaced en dash ` – `.
- A colon has no space before it and a lower-case word after it, unless a name follows. No comma before `și`, `sau`
  in a list.
- `·` stays as the separator. `×` stays in "2×" and in "{{width}}×{{height}}".
- No exclamation marks. No emoji.

### Length

Romanian runs about a quarter longer than the English, and `?lang=pseudo` shows what is cut at +35%. Where the place is
tight (the project's pill, chips, shortcut names, the transport), take the shorter word this page offers; don't
abbreviate words the page doesn't abbreviate. `Previzualizare`, `Dezinstalează` and `Redenumește` are the long ones to
look at in Romanian screenshots.

### For moongetsu to check first

1. **shot = plan, frame = cadru.** Editors may say `cadru` for a shot in speech. `plan` keeps a shot apart from
   `cadre pe secundă`, but your ear decides.
2. **pack = scenepack**, plural `scenepackuri`, or does the community say `pack`?
3. **folder, not dosar.** A change from the design's example ("Alege dosarul"): Windows and most people say `folder`;
   `dosar` is Apple's word.
4. **in / out = intrare / ieșire**, or `in` / `out` as editors say them? "Marchează in" reads oddly, which is why it
   isn't the draft. The player's two chips are the one place the choice shows in the layout: with the longer words the
   transport row gives up its timecodes and labels a few dozen pixels sooner than English's. Short `In` / `Out` on
   the chips alone would keep Romanian's tiers where English's are (`player:transport.in`, `.out`).
5. **handles = margini**, or `handles`?
6. **review:** `verificare` for faces, as the design proposed, and `revizuire` for plugins, a change from it, so that
   a human review doesn't read like the hash check.
7. **timeline stays**, as timecode does, rather than `cronologie`.
8. **Shot sizes** and the badges GP, PP, PA, PM, PG.
9. **Fast Scan = Scanare rapidă.** It is a feature, not a product, so it is translated.
10. **sandbox = mediu izolat**, **Live action = Cu actori reali**, and the frame unit `c`.
